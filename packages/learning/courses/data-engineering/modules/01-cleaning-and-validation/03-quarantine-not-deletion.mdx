When validation separates records into valid and invalid collections, the default impulse is often to ingest the valid records and ignore the rest:

```python
load(valid)
```

Discarding invalid records allows pipelines to finish without runtime exceptions, but causes downstream calculations to misrepresent the underlying source events.

## The cost of silent record dropping

Suppose one hundred out of ten thousand records fail validation because an upstream service changed `quantity` from `"2"` to `"2 items"`.

Discarding these records reduces total reported revenue by the sum of those one hundred transactions. Downstream reports render normally, but the aggregated numbers are incorrect. Silent omissions rarely trigger alerts.

Retaining rejected records in a quarantine store does not immediately correct the revenue total (the invalid rows are not yet loaded), but it records the full payload along with the reason: `not an integer: '2 items'`. Data teams can pinpoint when the schema divergence began and quantify the discrepancy.

Findability separates issues discovered and resolved within hours from discrepancies detected quarters later during financial reconciliations.

## Structure of a quarantine record

A quarantine record must retain the unparsed payload alongside error metadata:

```python
{
    "row_number": 6,
    "received_at": "2026-03-06T02:00:00Z",
    "source": "orders_2026-03-06.csv",
    "errors": [{"field": "quantity", "value": "unknown", "problem": "not an integer"}],
    "raw": {"order_id": "1006", "quantity": "unknown", ...},
}
```

Preserving the unmodified source record enables replayability. Once an upstream bug is fixed or a parsing rule is updated, quarantined records can be reprocessed through the validation pipeline without requiring source file retrieval from cold storage.

## Durability of quarantine storage

A quarantine system requires structured, queryable persistence, such as a database table or partitioned storage location. Transient standard output or log streams with short retention periods do not provide reliable audit capabilities.

A functioning quarantine system allows engineers to query aggregate failure counts, failure reasons, and affected time ranges with standard SQL queries.

## Monitoring error rates and threshold shifts

Absolute error counts are less informative than error rates relative to historical baselines.

A pipeline that consistently rejects two rows per run is operating within expected noise parameters. A sudden jump to two hundred rejections indicates upstream schema changes or transmission corruption. Comparing error rates across consecutive runs with an alert threshold flags anomalies before downstream consumers rely on incomplete datasets.
