Extract files frequently contain duplicate records caused by upstream network timeouts and automatic retries.

Defining a `PRIMARY KEY` on `order_id` turns duplicate entries into an explicit condition that the ingestion process must handle.

## Handling primary key conflicts during ingestion

Relational databases offer several strategies for handling insertion conflicts:

- **Standard `INSERT`:** Raises an `IntegrityError` upon encountering a duplicate key. The transaction aborts immediately, making it appropriate when duplicates indicate systemic corruption.
- **`INSERT OR IGNORE`:** Retains the existing record and discards the incoming one. This functions well when duplicates are identical retries. However, `OR IGNORE` suppresses all constraint violations, including unexpected `NOT NULL` failures.
- **Targeted `ON CONFLICT DO NOTHING`:** Specifying the conflict target explicitly (`ON CONFLICT(order_id) DO NOTHING`) handles duplicates on the primary key while allowing other constraint violations to raise errors:

```python
c.execute("INSERT OR IGNORE INTO t VALUES (2, NULL)")   # suppresses NOT NULL error
c.execute("INSERT INTO t VALUES (2, NULL) ON CONFLICT(id) DO NOTHING")
# IntegrityError: NOT NULL constraint failed
```

- **`INSERT OR REPLACE`:** Overwrites the existing record with the incoming row. In SQLite, this deletes and re-inserts the row, which triggers cascading deletes on tables with `ON DELETE CASCADE` foreign keys.
- **`ON CONFLICT DO UPDATE` (Upsert):** Updates specified columns on collision while preserving unmodified attributes. This is the standard pattern for incremental synchronization.

When duplicate records are completely identical, ignoring the second occurrence is safe, provided the pipeline verifies that row contents match.

## Schema definitions and type constraints

```sql
CREATE TABLE orders (
    order_id   INTEGER PRIMARY KEY,
    customer   TEXT NOT NULL,
    placed_at  TEXT NOT NULL,
    quantity   INTEGER,
    total      TEXT NOT NULL,
    status     TEXT NOT NULL
) STRICT;
```

This schema encodes specific domain rules:

- `quantity` is nullable because orders can ship with unknown item counts, while `customer` is marked `NOT NULL` because unassigned orders are invalid.
- `total` uses `TEXT` to preserve exact decimal values without floating-point rounding errors.
- `placed_at` stores ISO 8601 strings, which sort lexicographically and allow native chronological comparisons in SQLite.
