In-memory data structures like lists of dictionaries allow arbitrary keys and variable types. While flexible during initial prototyping, they rely on application-level discipline to maintain consistency.

## Invariant enforcement in relational tables

In-memory collections cannot enforce structural constraints:

- Duplicate records with identical identifiers can be appended freely.
- Type consistency depends entirely on application code paths, allowing strings and integers to coexist in the same conceptual column.
- Null values can appear in columns expected to be populated.
- Foreign key relationships to nonexistent parent entities remain undetected.

A database table enforces constraints directly at the storage level:

- `PRIMARY KEY` rejects duplicate entity identifiers.
- Column data types specify and validate expected representations.
- `NOT NULL` constraints reject incomplete records.
- `REFERENCES` foreign keys prevent orphan child records.

Enforcing constraints at the database boundary ensures that data integrity rules apply consistently to all current and future write paths.

## SQLite type affinity and strict mode

Python includes `sqlite3` in its standard library, providing a self-contained, serverless relational database engine.

By default, SQLite uses **type affinity** rather than rigid type enforcement. Declaring a column as `INTEGER` and inserting the string `"two"` succeeds, storing the text value directly:

```sql
CREATE TABLE orders (quantity INTEGER);
INSERT INTO orders VALUES ('two');   -- accepted
```

In default SQLite tables, column types act as conversion recommendations rather than strict guarantees. Input validation at the ingestion boundary remains necessary to ensure type safety.

Modern SQLite versions support `STRICT` tables, which reject values that do not match declared data types. Specifying `STRICT` during table creation enforces strict typing at the engine level.

## Parameterized queries and statement security

Database operations must use parameter substitution rather than string interpolation:

```python
cursor.execute(f"INSERT INTO orders VALUES ('{order_id}')")   # unsafe
cursor.execute("INSERT INTO orders VALUES (?)", (order_id,))  # safe
```

String interpolation introduces SQL syntax errors whenever values contain characters like apostrophes or quotes, and exposes databases to injection vulnerabilities. Parameterized queries escape inputs correctly and enable query plan caching.

## Transaction boundaries during batch loads

Executing individual `INSERT` statements with auto-commit triggers disk synchronization (`fsync`) on every row, slowing down bulk ingestion. Grouping inserts within explicit transactions commits data in batches.

Transactions also provide atomic isolation: either the entire batch commits successfully, or the entire operation rolls back on error. Ingestion jobs that fail without transactions leave tables partially populated with untracked subsets of data.
