Five modules, one idea: **a pipeline is a promise about data that has to keep being true
tomorrow**. This lesson makes the promise explicit, because a promise nobody wrote down is a
promise nobody can hold you to and, more usefully, one nobody can rely on.

## What a contract says

A data contract is the answer to "what can I assume about this table". Four things:

**Shape.** These columns, these types, these are nullable and these are not. You have this
already — it is the `CREATE TABLE` in
[loading a table](lesson:de-storage.loading-a-table), plus the validator from
[a schema that reports](lesson:de-cleaning.a-schema-that-reports).

**Grain.** One row per what. "One row per order" is the single most important sentence about a
table and the one most often absent, and every double-counting bug in this course came from
somebody assuming a different grain from the one they got — the explode in
[shapes that nest](lesson:de-records.shapes-that-nest) and the multiplying join in
[the rows a join loses](lesson:de-storage.the-rows-a-join-loses) are the same bug arriving
twice.

**Freshness.** How current this is, and how you will know when it is not.

**Semantics.** What the columns mean. `total` includes tax and excludes shipping. `status` is
the status at load time and not now. Nothing in the schema can say either of those, and both
are things somebody will otherwise assume wrongly.

## The contract is a test, or it is a wiki page

A contract written in a document is a description of how things were when somebody last
looked. Written as checks that run, it is a description of how things are.

Every promise above maps onto something from this course. Shape is the validator. Grain is the
uniqueness check from [counting is a test](lesson:de-contracts.counting-is-a-test). Freshness
is the previous lesson. Semantics is the only one that cannot be tested directly, and even it
usually has a proxy: "total includes tax" implies `total >= subtotal`, and that is a check.

So the contract is not a new artefact. It is the checks you already have, gathered in one file,
with the sentence each of them is defending written next to it.

## Breaking a contract on purpose

Contracts change. A column gets added, a meaning gets refined, a grain genuinely needs to
change.

What makes that survivable is that the contract is somewhere consumers can see, and that
breaking it is a visible act rather than a deploy that quietly starts producing different
numbers. Adding a column breaks nothing. Removing one, renaming one, changing a grain, or
changing what a value means, break everything downstream and cannot be detected by anybody
downstream.

The useful discipline is small: additive changes go out whenever, and anything else needs the
consumers told first. That is not process for its own sake. It is that every alternative ends
with somebody's report silently changing.

## What this course was

You read a messy file without a library, and learned what the library is doing. You coerced
values with a function that could admit it failed, validated a whole extract instead of one
row, and quarantined the failures instead of dropping them. You put it in a table with
constraints that refuse, read a query plan, and counted what a join threw away. You made a load
idempotent, gave it a watermark that does not lose the boundary row, backfilled with the same
code as the daily run, and made it resumable. Then you counted rows, checked freshness, and
wrote the promise down.

None of it was clever. Every hard part was noticing that something could go wrong quietly, and
adding the small boring thing that makes it go wrong loudly instead. That is the job.

## Where to go next

sqlite has taken you further than most people expect and there is a point where it stops. When
you reach it, the words to look up are Postgres, columnar formats like Parquet, and an
orchestrator such as Airflow or Dagster.

None of that changes anything you have learned here. An orchestrator is the run log from
[the partial run](lesson:de-pipelines.the-partial-run) with a web page on it. A warehouse is a
table with better indexes. The promise, and the checks that keep it, are the same.
