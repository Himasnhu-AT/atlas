A language model takes a sequence of input tokens and calculates a score for every token in its vocabulary. A decoding algorithm selects one token from this distribution, appends it to the sequence, and runs the forward pass again.

Every agent system, prompt framework, tool dispatch loop, and retrieval pipeline builds on this core operation. Understanding the mechanics of token prediction clarifies why models exhibit specific failure modes and cost dynamics.

## One forward pass, one distribution

Given an input token sequence, a model runs a single forward pass and outputs a vector of unnormalized scores called logits, with one float value per vocabulary entry. Model vocabularies typically contain 32,000 to 128,000 tokens. A softmax operation converts these raw logits into a normalized probability distribution summing to 1.0. A separate sampling step then selects the next token:

```python
logits = model(tokens)       # one float per vocabulary entry
probs = softmax(logits)      # sums to 1.0
next_token = pick(probs)     # not the model's job
```

The model architecture produces only the probability distribution. Token selection is handled independently by the decoding sampler using configured parameters like temperature and top-p.

The distribution reflects patterns learned from pre-training and alignment training, prioritizing continuations that match instruction-following patterns. It does not measure ground truth; the model architecture evaluates statistical likelihood across token sequences rather than factual validity.

## Autoregression and sequential generation

To generate text, the model executes iteratively. It generates one token, appends that token to the input sequence, and performs another forward pass:

```python
tokens = tokenize(prompt)
for _ in range(max_new_tokens):
    token = pick(softmax(model(tokens)))
    if token == STOP:
        break
    tokens.append(token)
```

This autoregressive process establishes two operational characteristics:
1. Input processing and output generation differ in execution. Prompt tokens are processed in parallel during an initial forward pass (time-to-first-token). Generated output tokens require sequential passes, producing a steady token stream at a constant decoding rate.
2. The model conditions on its own prior generations. An erroneous token generated early in a response becomes part of the context for all subsequent tokens. The model maintains stylistic and structural coherence from that premise.

Under causal attention, each token's attention key and value vectors depend solely on preceding tokens. Serving systems cache these vectors in a key-value (KV) cache. Each subsequent step computes values for the newest token and attends to the cached representations, avoiding redundant computation across past tokens.

## Hallucinations and calibration

When a model generates an incorrect citation or invalid fact with apparent confidence, it is completing patterns rather than verifying statements.

Logit values measure sequence likelihood given the context. Two architectural factors explain why ungrounded outputs occur:
1. Softmax normalization forces all output probabilities to sum to 1.0. The model must distribute probability mass across its fixed vocabulary even when no suitable continuation exists in its training weights.
2. Prediction operates at the token level. Following the prefix `Smith et al. (`, the highest probability continuation is a four-digit year (such as `2021`). The model assigns high probability to the numeric format of a citation based on syntactic convention, without assessing whether the cited work exists.

Directives like "never make anything up" cannot ground facts absent from the model weights. Effective mitigations require structural patterns: providing factual context via retrieval, supplying lookup tools, or validating outputs against external schemas and deterministic checks.

## Training versus inference

Model weights remain static during inference. Every runtime capability depends on the token sequence passed in the request.

Consider this three-turn interaction:

```python
# Call 1. Wrong answer.
messages = [{"role": "user", "content": "Who wrote Dune?"}]
reply = ask(messages)                     # "Isaac Asimov."

# Call 2. Same session, so the correction is in the array.
messages += [
    {"role": "assistant", "content": reply},
    {"role": "user", "content": "No, Frank Herbert. Who wrote Dune?"},
]
ask(messages)                             # "Frank Herbert." Looks like learning.

# Call 3. New session. Nothing carried over but the weights, which never moved.
ask([{"role": "user", "content": "Who wrote Dune?"}])   # "Isaac Asimov." again.
```

In call 2, the model generates the correct author because the answer was provided in the input context. In call 3, starting a new session resets the input array to a single prompt, reproducing the initial error.

| Phase | State location | Persistence across requests |
| --- | --- | --- |
| Training and fine-tuning | Model weights | Persistent |
| Request context | Token array | Ephemeral (single call) |

Agent memory is an application-level abstraction. Techniques like few-shot examples, retrieved context, tool outputs, and message history all manipulate the ephemeral input sequence.

## Reasoning models and test-time compute

Reasoning models generate intermediate thinking tokens before emitting a final response. On tasks with verifiable logic (such as mathematical derivation and code generation), this extended computation improves accuracy.

The underlying mechanics remain autoregressive: intermediate tokens are sampled step-by-step from logit distributions. These models are trained using reinforcement learning against final answer correctness, allowing the system to learn effective problem-solving trajectories.

Intermediate tokens provide explicit scratchpad space. Because each token feeds into subsequent forward passes, the model can adjust its path upon identifying an inconsistent intermediate step.

Reasoning tokens consume output limits, add execution latency, and incur standard completion token costs. They benefit complex reasoning tasks with deterministic solutions, but they do not supply domain knowledge missing from the training data.

## State management implications

The model retains no state between requests. Every API call evaluates a standalone sequence against fixed model weights.

Consequently, multi-turn dialogues require resending the entire message history on every turn. An agent loop executing eight tool calls resends the growing transcript eight consecutive times. While providers offer prompt caching for repeated prefixes, the full sequence must still fit within the model's context budget.
