A language model outputs raw logit scores for every vocabulary token. A downstream sampling algorithm converts these logits into token choices. The parameters governing this step (including temperature, top-p, and top-k) are applied in software after the forward pass completes.

## Converting logits to probabilities with softmax

Logits are unconstrained real values representing relative token preferences. The softmax function exponentiates logits and normalizes them into a probability distribution:

```python
def softmax(logits):
    ceiling = max(logits)                       # subtract the max first
    weights = [math.exp(x - ceiling) for x in logits]
    total = sum(weights)
    return [w / total for w in weights]
```

Subtracting `max(logits)` before exponentiation provides numerical stability. Because `math.exp(x)` overflows double precision floats near `x = 709` (and overflows half precision floats at much lower values), subtracting the maximum logit shifts the maximum exponent to `0.0`. This ensures `exp(0.0) == 1.0` and guarantees that all scaled weights fall in the interval `(0.0, 1.0]`. The mathematical output remains identical:

```
exp(x - c) / sum(exp(xi - c))  ==  exp(x) / sum(exp(xi))
```

The probability ratio between any two tokens depends solely on the difference between their logits. Scaling these differences reshapes the distribution.

## Greedy decoding and temperature scaling

Greedy decoding selects the token with the highest logit (`argmax`), yielding deterministic outputs for fixed inputs.

Temperature scaling divides the raw logits by a positive float `T` before applying softmax:

```python
def apply_temperature(logits, temperature):
    return [x / temperature for x in logits]
```

- When `T < 1.0`, logit differences are amplified, sharpening the distribution toward the top tokens.
- When `T > 1.0`, logit differences are compressed, flattening the distribution and increasing the probability mass assigned to lower-ranked tokens.
- `T = 0.0` represents greedy decoding. Division by zero is undefined in arithmetic, so implementations handle `T = 0.0` as a conditional branch returning `argmax(logits)`.

Consider logits `[3.0, 2.0, 1.0, 0.0]` across different temperature values:

| Temperature | Resulting probabilities |
| --- | --- |
| 0 | 1.00, 0.00, 0.00, 0.00 |
| 0.7 | 0.76, 0.18, 0.04, 0.01 |
| 1.0 | 0.64, 0.24, 0.09, 0.03 |
| 1.5 | 0.52, 0.27, 0.14, 0.07 |

At `T = 1.5`, probability shifts into the long tail of vocabulary tokens. In full vocabularies with over 100,000 entries, high temperatures distribute probability across thousands of low-ranking tokens. Because generation is autoregressive, selecting an unnatural tail token incorporates it into context for all subsequent steps.

## Truncating the distribution tail

To prevent improbable tokens from being sampled, sampling filters truncate the distribution tail before selection.

Top-k filtering retains the `k` highest probability tokens, sets all other probabilities to zero, and renormalizes the surviving values.

Top-p filtering (nucleus sampling) sorts tokens by probability descending, accumulates cumulative probability, and retains the smallest subset whose sum reaches threshold `p`.

| Distribution property | Confident state | High-entropy state |
| --- | --- | --- |
| Probabilities | 0.90, 0.05, 0.03, 0.01, 0.01 | 0.25, 0.22, 0.20, 0.18, 0.15 |
| Cumulative sum | 0.90, 0.95, 0.98, 0.99, 1.00 | 0.25, 0.47, 0.67, 0.85, 1.00 |
| Top-k (k=2) | Keeps 2 tokens | Keeps 2 tokens |
| Top-p (p=0.9) | Keeps 1 token | Keeps 5 tokens |

Top-p dynamically adapts candidate set size based on model confidence. When one token dominates the distribution, top-p restricts sampling to that single candidate. When probability is dispersed, top-p expands candidate selection to maintain coverage.

These operations compose sequentially: apply temperature to logits, run softmax, apply top-k, apply top-p, and sample from the normalized result:

```python
probs = softmax(apply_temperature(logits, temperature))
probs = top_k_filter(probs, k)
probs = top_p_filter(probs, p)
token = sample(probs, rng)
```

## Limits of runtime determinism

Setting `temperature = 0` makes the sampling step deterministic. However, production inference can still exhibit slight variance across requests due to GPU floating-point non-associativity in batched matrix operations. Small variations in logit precision can alter top-ranked tokens when scores are close.

To test agent logic reliably, write unit tests against structural properties: schema validation, tool invocation targets, and required field presence.

## Selecting configuration values

Configure sampling parameters according to task type:
- Extraction, classification, and tool calling: use `temperature = 0.0` or low values (`0.0` to `0.2`) with `top_p = 1.0` to maximize consistency.
- Open-ended generation: use `temperature = 0.7` to `1.0` and `top_p = 0.9`.

Adjust one parameter at a time during evaluation to isolate causal effects. Sampling controls alter selection probability, but cannot supply missing facts; ungrounded answers at `T = 0.0` require prompt adjustments, few-shot demonstrations, or external retrieval.
