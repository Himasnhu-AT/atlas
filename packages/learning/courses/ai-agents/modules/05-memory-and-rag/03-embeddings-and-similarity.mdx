Retrieval systems require a method to determine semantic relevance between user queries and document chunks
without requiring exact keyword overlap. Embedding models provide this mapping.

## What an embedding represents

An embedding model maps text strings into fixed-length vectors of floating-point numbers. Both a short query
and a multi-paragraph document map to vectors of identical dimensionality.

Trained embedding models position semantically related texts close together in vector space. Individual dimensions
do not correspond to discrete human concepts. Relevance is determined solely by geometric distance or angle
relative to other vectors in the same space.

Vectors are comparable only when generated by the same embedding model. Upgrading or changing the embedding model
requires re-indexing the entire document corpus.

## Cosine similarity and dot product

```widget:vector-space
  - id: "pricing-doc"

    x: 0.68
    y: 0.45
  - id: "api-doc"
    label: "api_auth_keys.md"
    x: -0.45
    y: 0.70
  - id: "troubleshoot-doc"
    label: "error_codes.md"
    x: -0.60
    y: -0.30
```

Cosine similarity measures the angle between two vectors, normalizing for vector magnitude:

```python
def cosine_similarity(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    return dot / (math.sqrt(sum(x * x for x in a)) * math.sqrt(sum(y * y for y in b)))
```

Normalizing magnitude ensures document length does not distort semantic similarity scores.

When embedding providers return unit-normalized vectors (magnitude equal to 1), cosine similarity equals the
dot product of the two vectors.

Cosine similarity ranges from -1 to 1. The score represents an angular metric rather than an absolute percentage;
scores are meaningful primarily when compared relative to other candidates for the same query.

## Hashed embeddings in testing environments

In this course, `mockllm.embed_text` uses a deterministic hashing method: text is tokenized into words and hashed
into 256 vector buckets.

This provides real vector representations for testing rankings, thresholds, and top-k operations without requiring
external API calls.

Hashed embeddings capture keyword overlap but do not resolve semantic paraphrases. For example, "how long until
I get my money back" will not match "billing-refunds" using word hashing because the terms share no vocabulary.
Production systems replace hashed vectors with neural embedding APIs to support semantic paraphrase matching.

## Linear scanning versus vector stores

For collections containing up to several tens of thousands of chunks, exact linear scanning in Python is fast and
deterministic:

```python
query_vector = client.embeddings.create(input=query).data[0].embedding
scored = [
    (cosine_similarity(query_vector, vector), position, document)
    for position, (vector, document) in enumerate(zip(index.vectors, index.documents))
]
scored.sort(key=lambda item: (-item[0], item[1]))
```

Sorting by score descending and position ascending ensures deterministic tie-breaking.

Dedicated vector databases become useful when systems require:
- Persistent disk-backed vector storage.
- Real-time updates and deletions.
- Metadata filtering across user or tenant security boundaries.
- Approximate Nearest Neighbor (ANN) indexing (such as HNSW graphs) when corpus size makes linear scans a latency bottleneck.

## Confidence thresholds and ambiguity margins

Retrieval systems must balance three configuration parameters:

1. Top-k count: Defines the maximum number of candidates injected into the prompt. Higher values improve recall
at the expense of increased prompt token usage and latency.

2. Score threshold: Enforces a minimum similarity floor. Without a threshold, the retriever always returns the
highest-scoring candidate, even when the query is completely unrelated to the corpus. A minimum threshold enables
the system to return empty results when no relevant documents exist.

3. Ambiguity margin: Evaluates the score delta between the top-scoring candidate and runner-up candidates.
When top candidates score within a narrow margin (e.g. delta less than 0.02), candidate ranking is ambiguous.
Identifying ambiguous results allows systems to request user clarification or expand context rather than
arbitrarily selecting a candidate.
