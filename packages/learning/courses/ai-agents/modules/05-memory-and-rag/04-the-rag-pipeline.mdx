A complete retrieval-augmented generation pipeline connects document ingestion, vector retrieval, prompt assembly,
and model generation. The critical operational details lie in formatting retrieved context and managing queries
that lack relevant documentation.

## Ingestion and query execution phases

RAG systems operate across two distinct lifecycles:

Ingestion runs offline when documents change. The pipeline splits documents into chunks, attaches metadata,
generates embeddings in batches, and updates the vector store:

```python
store.add(all_chunks)          # batch embedding request
```

Batching embedding requests prevents hitting API rate limits and avoids unnecessary network round-trip overhead.

Query execution runs online per user question:
1. Embed the query text.
2. Search candidate chunks.
3. Filter out chunks scoring below the similarity threshold.
4. Format surviving chunks into the prompt context.
5. Generate the completion.

## Context formatting and block layout

Retrieved chunks must be combined into a structured string block:

```
[1] pricing.md#0
The Pro plan includes unlimited projects and priority support.

[2] pricing.md#1
The Pro plan costs $49 per month when billed annually.
```

This layout serves three structural requirements:
- Bracketed indices (`[1]`, `[2]`) provide simple numeric identifiers for model citations in generated text.
- File and section paths next to indices allow developers and downstream verification tools to resolve citations
back to source documents.
- Explicit blank lines between chunk blocks prevent models from treating separate passages as a single continuous text.

### Preserving raw chunk text

Chunk text must be inserted into prompt templates without modification or escaping. Downstream verification steps
match cited quotes directly against original document texts; modifying chunk text during assembly breaks text matching.

## Enforcing grounded generation

The system prompt enforces citation compliance and defines explicit refusal behavior:

```python
SYSTEM_PROMPT = (
    "You answer questions using only the context provided in this conversation.\n"
    "Every factual sentence must end with the bracketed number of the source it "
    "came from, like [1].\n"
    f'If the context does not answer the question, reply exactly: "{NO_ANSWER}"\n'
    "Do not use anything you know outside the context."
)
```

Specifying an exact refusal string (`NO_ANSWER`) ensures programmatic callers can detect refusals without heuristic text parsing.

Prompt instructions are paired with minimum score thresholds at the retrieval layer:

```python
hits = [hit for hit in store.search(question, k=k) if hit.score >= min_score]
if not hits:
    return Answer(NO_ANSWER, [], grounded=False)
```

Filtering at the retrieval layer prevents irrelevant context from reaching the model, eliminating token costs for
unanswerable queries.

## Disentangling retrieved sources from cited claims

The `Answer` object distinguishes between retrieved sources and model citations:

```python
return Answer(
    text=reply,
    sources=[hit.chunk.citation() for hit in hits],
    grounded=True,
)
```

The `sources` list records what the retrieval engine supplied in the prompt. The bracketed citations within `reply`
represent the claims made by the model.

Tracking both values enables automated verification. [Grounded answers and scope](lesson:ai-support-triage.grounded-answers-and-scope)
flags citations that reference unretrieved source IDs. [The verification pass](lesson:ai-research-briefing.the-verification-pass)
validates that generated quotes match the underlying source documents.

## Evaluating retrieval separately from generation

Evaluating RAG performance requires measuring retrieval and generation independently:

Retrieval quality measures whether relevant document chunks appear in the top-k results. Benchmark retrieval
using labeled query-document pairs without invoking the generation LLM, as established in [chunking](lesson:ai-memory-and-rag.chunking).

Consider this ranking for "How much does the Pro plan cost?":

```
pricing.md#0     0.4781   The Pro plan includes unlimited projects and priority support.
pricing.md#1     0.3419   The Pro plan costs $49 per month when billed annually.
pricing.md#2     0.2097   The Free plan is limited to three projects...
```

The chunk containing the price ranks second behind a chunk with high vocabulary overlap. If `k=1`, retrieval fails
despite valid chunking. Measuring retrieval in isolation reveals these boundary issues.

Generation quality measures whether the model's answer is accurate, well-cited, and faithful to the provided context.
Separate evaluation metrics ensure that prompt engineering and retrieval tuning can be optimized independently.
