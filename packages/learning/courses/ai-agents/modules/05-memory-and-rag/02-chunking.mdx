Documents must be partitioned into chunks because the chunk serves as both the retrieval unit and the context
payload injected into the prompt. Retrieving whole documents floods the prompt with irrelevant text, whereas
retrieving isolated sentences loses essential surrounding context.

Effective chunking produces segments small enough to be semantically specific, yet large enough to remain
self-contained.

## Four document splitting strategies

| Strategy | Split boundary | Preserves | Failure mode |
| --- | --- | --- | --- |
| Fixed size | Character or token counts | Uniform size | Breaks sentences, paragraphs, code blocks, tables |
| Paragraph or sentence | Punctuation or blank lines | Complete thoughts | Splits cross-paragraph concepts; uneven chunk sizes |
| Structural | Markdown headers, HTML tags, AST nodes | Document hierarchy | Requires well-structured source markup |
| Recursive character | Coarsest matching separator | Semantic structure with fallback | Complex splitting logic |

Fixed-size chunking provides a baseline for unstructured text (such as unformatted OCR scans) where semantic
delimiters are absent.

Structural splitting uses document markup. Splitting Markdown on heading tags preserves logical document sections
while attaching heading text as metadata.

Recursive character splitting balances semantic boundaries with size constraints. It attempts to split text using
a hierarchy of separators: double newlines, single newlines, sentence punctuation, and spaces.

The recursive implementation must pass remaining separators down the stack:

```python
if len(piece) > max_size:
    chunks.extend(split_recursive(piece, max_size, rest))
```

Passing `rest` (the remaining separator list) guarantees termination. Passing the full list causes infinite
recursion when a separator fails to reduce chunk size below `max_size`.

After splitting on coarse separators, implement a greedy merge pass to combine adjacent small segments while they
remain under `max_size`. Omitting the merge pass produces fragmented one-line chunks lacking semantic context.

## Overlap and its trade-offs

Chunk overlap duplicates the end of one chunk at the beginning of the next, preventing key facts from being
severed across chunk boundaries:

```python
step = size - overlap
for start in range(0, len(text), step):
    windows.append(text[start : start + size])
```

Overlap introduces specific costs:
- Increases total vector count, embedding computation, and index storage.
- Generates near-duplicate retrieval results. If two top-ranking chunks cover the same overlapping text, context
space is consumed by duplicate information.

Overlap is essential for fixed-size splitting where boundaries fall arbitrarily. For structure-aware splitters,
semantic boundaries reduce the need for large overlap windows.

## Chunk size considerations

Optimal chunk size depends on corpus characteristics and query types:
- Smaller chunks (e.g. 200 to 400 characters) provide precise vector matches for specific factual lookups but
risk missing surrounding background context.
- Larger chunks (e.g. 1000 to 2000 characters) retain complete context but dilute embedding representations
across multiple topics, potentially reducing search precision.

Evaluate chunking strategies against a benchmark dataset of representative domain queries and target documents
to determine optimal sizing.

System designs can also expand small retrieved chunks at query time by fetching neighboring chunks using stored
document position indices.

## Preserving metadata for citations

Each chunk must track its source document, sequence index, and structural headings:

```python
def with_context(self) -> str:
    parts = [p for p in (self.metadata.get("title"), self.metadata.get("section")) if p]
    if not parts:
        return self.text
    return f"{' > '.join(parts)}\n\n{self.text}"
```

Prefixing hierarchical headings (such as section titles) into the text before embedding ensures queries match
relevant document sections, even when individual chunks lack explicit topic keywords.

Embed the contextualized text string for retrieval, but display the original chunk body when constructing citations.
