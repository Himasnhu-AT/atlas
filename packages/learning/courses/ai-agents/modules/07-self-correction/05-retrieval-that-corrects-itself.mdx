In [The RAG pipeline](lesson:ai-memory-and-rag.the-rag-pipeline), the standard workflow follows four deterministic steps: embed the query, retrieve the top k nearest chunks, insert them into the prompt context, and generate an answer.

This standard implementation operates on two key assumptions:
1. The top k retrieved chunks contain relevant information. In practice, vector similarity search returns nearest neighbors even when the corpus has no relevant content for the query.
2. Every incoming turn requires document retrieval. Routine pleasantries or self-contained conversational turns unnecessarily trigger embeddings and inject irrelevant context.

Applying self-correction principles to retrieval improves accuracy because the retriever can actively query new facts rather than relying solely on parametric weights.

## Evaluating retrieved chunks

To address irrelevant retrievals, add a grading step between retrieval and synthesis that evaluates each chunk against the incoming query:

**Relevant.** The chunk contains information that directly answers the user query. Retain for context assembly.

**Irrelevant.** The chunk is tangential or unhelpful despite vector similarity score. Discard to prevent noisy tokens from diluting attention.

**Ambiguous.** The chunk provides partial context. Retain with an explicit uncertainty flag, matching the pattern in [chain of verification](lesson:ai-self-correction.chain-of-verification).

When all retrieved chunks are graded as irrelevant, the pipeline detects a retrieval failure before attempting to generate an answer.

## Corrective actions on retrieval failure

Detecting an inadequate retrieval set enables targeted corrective steps:

**Query rewriting.** Users often phrase questions differently from technical documentation (for example, asking *"why did my card get declined"* when the manual discusses *"error 402: payment method rejected"*). Rewriting the query using terminology aligned with the corpus frequently surfaces the intended chunks.

**Index broadening.** Increase retrieval depth or relax metadata filters that may have excluded relevant documents.

**Honest fallback.** When the corpus does not contain the required facts, the system should explicitly state that the information is unavailable. This fulfills the scope requirement detailed in [grounded answers and the scope boundary](lesson:ai-support-triage.grounded-answers-and-scope).

Corrective loops must enforce a maximum retry count (such as two re-query attempts) to prevent runaway query drift.

## Deciding when to retrieve

To avoid unnecessary lookups, place a lightweight classification check before running vector search to determine whether the prompt requires external documentation.

This routing step skips vector search for general conversational turns, queries that can be answered from recent conversation history, or basic clarification prompts. Bypassing retrieval for non-factual queries reduces latency and prevents irrelevant context from crowding the prompt.

When routing confidence is borderline, default to retrieving. An unnecessary retrieval consumes additional tokens, whereas an erroneously skipped retrieval risks producing an ungrounded hallucination.

## Taxonomy: corrective, adaptive, and self-RAG

Literature frequently distinguishes three related patterns:

**Corrective RAG (CRAG).** Evaluates retrieved documents for relevance and triggers query rewriting when results are insufficient.

**Adaptive RAG.** Dynamically routes queries to determine whether retrieval is necessary, and selects appropriate retrieval strategies based on query complexity.

**Self-RAG.** Evaluates generated responses against retrieved context to confirm that every claim is grounded in the source text.

These three techniques compose naturally within a single production pipeline.
