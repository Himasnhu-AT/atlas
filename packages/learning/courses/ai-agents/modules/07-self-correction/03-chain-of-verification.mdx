Chain of verification replaces subjective self-critique with structured factual validation. Instead of asking whether an entire draft looks sound, the process decomposes the output into isolated propositions and evaluates each piece independently.

The methodology follows four sequential phases:

**1. Decomposition.** Extract discrete factual claims from the draft output.

**2. Question generation.** Convert each claim into a standalone query that can be evaluated without reference to the original response.

**3. Independent execution.** Answer each question in an isolated context window with previous conversational reasoning omitted.

**4. Reconciliation.** Compare the independent findings against the original draft claims, pruning or updating statements that conflict with verification results.

## Preserving context independence

The effectiveness of chain of verification depends directly on context isolation during execution:

```python
# Contextually biased: includes the proposed draft
verify(f"Draft: {draft}\n\nIs this claim true: {claim}?")

# Independent execution: evaluates the standalone factual query
verify(f"{question}")
```

The second approach removes the draft text, adjacent claims, and prior reasoning chains. When the independent evaluation diverges from the original claim, the discrepancy provides an actionable signal for correction.

Validation quality correlates directly with what is excluded from the verification prompt.

## Decomposition mechanics

Proper claim decomposition requires strict parsing rules:

**Atomic assertions.** A sentence like *"The 2019 model was released in March and sold 40,000 units"* contains two separate propositions: the release date and the unit sales volume. These should be split into individual claims so partial inaccuracies can be isolated.

**Resolution of coreferences.** Statements containing relative pronouns or chronological anchors (such as *"It was discontinued the following year"*) must resolve entity names and dates explicitly during decomposition.

**Separation of facts from opinions.** Evaluative statements such as *"The design represents a substantial improvement"* constitute subjective commentary rather than verifiable facts. The decomposition step filters out stylistic opinions and retains only checkable assertions.

## Reconciliation verdicts

Evaluating claims yields three distinct states, each requiring specific handling:

**Supported.** The independent answer confirms the claim, allowing it to remain in the final text.

**Contradicted.** The independent answer conflicts with the claim. Contradicted assertions are corrected using verified data or removed entirely.

**Unsupported.** The verification process yields inconclusive data. Unsupported claims are flagged rather than silently dropped or kept without review, mirroring the pattern in [quarantine, not deletion](lesson:de-cleaning.quarantine-not-deletion).

When reference documents are available, validating claims directly against source text provides stronger guarantees than querying a model without supporting context.
