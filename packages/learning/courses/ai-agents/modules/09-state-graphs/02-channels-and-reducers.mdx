Storing agent state in a raw dictionary creates concurrency problems. When two nodes
write to the same key during the same execution step, one write overwrites the other silently.

A channel wraps a dictionary field with two explicit properties: a reducer function defining
how updates combine with existing values, and a version counter that increments on every write.
The reducer resolves concurrent writes predictably, while the version counter drives the scheduler.

## How reducers merge updates

A reducer takes the current state value and an incoming update, returning the next state value.
Four basic reducers handle most agent workloads:

```python
def last_value(current, update):
    return update

def append(current, update):
    if isinstance(update, list):
        return list(current) + update
    return list(current) + [update]

def merge_dicts(current, update):
    return {**current, **update}

def add_int(current, update):
    return current + update
```

Reducers must create new data structures rather than mutating inputs in place. Checkpointers
store references or snapshots of state values across steps. If a reducer mutates a list in place via
`current.append(x)` and returns `current`, every historical checkpoint in the thread references the same
mutated object, corrupting step-by-step history.

Choosing reducers specifies state combination semantics explicitly:
- `last_value` on a `draft` channel keeps only the most recent output.
- `append` on a `findings` channel aggregates contributions from parallel research nodes.
- `add_int` on a `tokens_used` channel accumulates resource usage across all nodes.
- `merge_dicts` on `metadata` combines independent key-value attributes.

Default channel values should use factory callables (such as `list` or `dict`) rather than static
mutable objects, preventing shared references across distinct graph invocations.

## Version numbers drive scheduling

Every channel tracks an integer version counter starting at zero. Writing to a channel executes
its reducer and increments the version by one. The counter increments on every write operation,
even if the resulting value is identical to the previous value, signaling that a node produced an output.

The runtime maintains `versions_seen`, a mapping from node names to the channel versions observed
during each node's most recent execution. The scheduler evaluates node eligibility using this rule:

```python
def eligible_nodes(subscriptions, versions, versions_seen):
    stale = []
    for node, channels in subscriptions.items():
        seen = versions_seen.get(node, {})
        if any(versions.get(name, 0) > seen.get(name, 0) for name in channels):
            stale.append(node)
    return sorted(stale)
```

A node becomes eligible to run when at least one of its subscribed channels has a version strictly
greater than the version recorded in `versions_seen`. The condition requires a strict inequality (`>`);
using `>=` would cause unexecuted nodes at version zero to trigger indefinitely.

Sorting the resulting node list ensures deterministic execution and merge order across identical graph runs.

## Subscriptions versus read access

Nodes can access the full graph state when executing, but they only subscribe to the subset of channels
that should trigger subsequent execution.

For example, a summary node might read `question`, `findings`, and `budget`, but subscribe only to `findings`.
The node re-runs when new findings arrive, but remains idle when an unrelated node decrements `budget`.
Subscribing a node to channels it only reads passively causes unnecessary node wakeups and redundant model calls.

## Reducers and channels in LangGraph

LangGraph implements this design using type annotations on state dictionaries:

```python
from typing import Annotated, TypedDict
import operator

class State(TypedDict):
    findings: Annotated[list[str], operator.add]   # channel with append reducer
    draft: str                                     # channel with last_value reducer
```

`Annotated[list[str], operator.add]` declares an append reducer on the `findings` channel.
An unannotated `str` defaults to a `last_value` overwrite reducer. While LangGraph infers channel
subscriptions from graph edges, the runtime built in this module declares subscriptions explicitly
to make dependency tracking visible.

## Exercise overview

In this exercise, you will implement the core channel layer:
- The four standard reducers (`last_value`, `append`, `merge_dicts`, `add_int`).
- `ChannelState` to manage channel values, defaults, and version counters.
- `eligible_nodes` and `mark_seen` scheduling functions.

Key requirements:
1. `ChannelState.apply` must be atomic: if any channel name in an update batch is invalid, reject the batch without modifying state or versions.
2. Version counters must increment on every successful write, including writes where the value does not change.

Subsequent exercises build directly on this channel state implementation.
