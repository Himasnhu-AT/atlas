Executing a multi-agent research pipeline end to end connects the independently built stages into a unified workflow.

In production environments where research runs span multiple minutes and incur meaningful API costs,
system design must accommodate stage-level checkpointing, telemetry instrumentation, and continuous evaluation benchmarking.

## End-to-end pipeline assembly

The complete pipeline coordinates planning, worker extraction, brief synthesis, and verification under a shared budget:

```python
client = MockClient(script)        # OpenAI(...) in production
budget = Budget(limit=200_000)
search = make_search(CORPUS)

research = orchestrate(client, search, CORPUS, QUESTION, budget)
brief = write_brief(client, research)
report = verify_brief(
    client, brief, number_notes(research.notes), research.corpus, budget
)

print(brief.text if report.ok else redact_unverified(brief, report))
print(budget.by_stage, "->", budget.spent, "tokens")
print(f"{research.dropped} notes dropped, {report.supported} claims verified")
```

Important architectural seams in this integration:
- `verify_brief` receives `research.corpus` rather than global state, ensuring verification tests against the exact document snapshots retrieved during the run.
- The shared `budget` accumulates token consumption across each stage:

```
{'plan': 49, 'worker': 200, 'synthesis': 150, 'verify': 183} -> 582 tokens
1 notes dropped, 2 claims verified
```

- Verification spend scales with the number of generated claims rather than the number of initial sub-questions.
- `report.ok` controls whether the application outputs the raw brief or the redacted document with in-place markers.

## Checkpointed stage resumption

When a network failure occurs during later worker extractions, re-running the entire pipeline from scratch
wastes previously billed completions.

Persisting stage output to durable storage enables resumed runs to skip completed stages:

```python
def checkpoint(run_id: str, stage: str, payload: dict) -> None:
    path = STATE_DIR / f"{run_id}.json"
    state = json.loads(path.read_text()) if path.exists() else {}
    state[stage] = payload
    path.write_text(json.dumps(state))
```

Because sub-questions, worker extractions, and note tags are deterministically indexed, a resumed pipeline
resumes execution using existing checkpoint artifacts without altering downstream references.

## Privacy-preserving operational tracing

Production telemetry should record operational execution structure without storing raw sensitive document text:

```python
{"run_id": ..., "stage": "worker", "worker": "w2",
 "sub_query_hash": "9f2c...", "doc_ids": ["d-solar", "d-wind"],
 "notes_kept": 2, "notes_dropped": 1, "tokens": 812, "ms": 2140}
```

Logging document identifiers, query hashes, token counts, and dropped note tallies provides sufficient data
to detect cost regressions and prompt degradation while protecting user data privacy.

## Compact evaluation benchmark design

Continuous evaluation for research pipelines relies on a compact suite of benchmark questions (e.g. 10 to 15 cases)
evaluated against four core metrics:

- **Citation precision**: The ratio of supported claims (`report.supported / len(report.verifications)`).
- **Corpus coverage**: The proportion of target document IDs successfully referenced in the final brief.
- **Fabrication rate**: Sum of worker-level dropped notes (`research.dropped`) and verification-level source misses (`report.not_in_source`).
- **Stage cost**: Cumulative token usage recorded across `budget.by_stage`.

Keeping the benchmark suite compact ensures tests can run frequently in CI pipelines, detecting regressions
in claim accuracy or stage costs before deploying updates.

## Connecting to live provider endpoints

To run the complete research briefing pipeline against live provider endpoints:

1. Replace the mock client with an active OpenAI or compatible client:

```python
from openai import OpenAI
client = OpenAI(api_key=os.environ["OPENAI_API_KEY"], base_url=BASE_URL)
```

2. Replace the hash-based embedding helper with vector embeddings:

```python
def embed_text(content: str) -> list[float]:
    response = client.embeddings.create(model="text-embedding-3-small", input=content)
    return response.data[0].embedding
```

With dense vector embeddings, document retrieval handles semantic variations and synonyms naturally.
The planner, worker isolation boundaries, citation numbering, supervisor synthesis, and verification passes
remain completely unchanged.
