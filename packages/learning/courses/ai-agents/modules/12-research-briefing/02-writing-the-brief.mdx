Once parallel workers extract evidence from their respective document subsets, the system must
synthesize findings into a coherent brief.

Rather than having each worker draft independent prose paragraphs (which causes redundant introductions,
conflicting citation schemes, and token inflation), workers return raw note snippets. A single supervisor
invocation consumes all collected notes and writes the unified brief, leaving document structure and formatting
to deterministic Python code.

## Deterministic note indexing and tagging

Before providing notes to the supervisor prompt, assign deterministic source tags:

```
[S1] d-queue: The median wait is now five years.
[S2] d-solar: Solar module prices fell 41 percent last year.
[S3] d-solar: Installers passed half of the decline on.
[S4] d-storage: Grid battery storage additions doubled.
```

`number_notes` sorts entries by document ID and arrival index. Sorting ensures consistent tag assignment
across identical runs and automatically groups references by source document in the final bibliography.

The prompt instructs the model to:
1. Append the source tag (e.g. `[S2]`) to every factual claim supported by the notes.
2. Avoid stating facts not backed by the provided notes.
3. Explicitly state gaps when the notes do not address an aspect of the query, leaving those specific sentences untagged.

Untagged sentences are stored in `Brief.uncited`. Preserving uncited statements in the document while
flagging them in metadata provides transparency regarding which portions of the brief lack evidence.

## Sentence boundary splitting and claim parsing

Extracting structured claims from model prose requires reliable sentence boundary detection:

```python
_BOUNDARY = re.compile(r"(?<=[.!?])\s+")
```

Using lookbehind on punctuation preserves decimal numbers like `15.5` without splitting.
Abbreviations with trailing spaces (such as `e.g.`) are handled by recombining fragments based on preceding tokens.

Each extracted sentence maps to a `Claim` record:
- Tags matching assigned note indices populate `tags`.
- Hallucinated markers (such as `[S9]` when only four notes exist) route to `unknown_tags`.

Separating unknown tags prevents hallucinated citations from being treated as verified references during downstream verification.

## Programmatic document assembly

Construct the title and bibliography programmatically rather than delegating formatting to the model:

```python
lines = [f"Research brief: {research.question}", "", prose, "", "Sources"]
lines.extend(f"- {doc_id}: {titles[doc_id]}" for doc_id in sources)
```

Deriving the bibliography directly from cited claim records ensures that every listed document was
actually referenced in the body. The model's prose is preserved without reformatting to ensure downstream
verification passes can locate exact sentence offsets.

## Supervisor patterns in agent frameworks

Major agent frameworks structure this synthesis stage through manager or coordinator abstractions:

```python
# Reference example using OpenAI Agents SDK
supervisor = Agent(
    name="supervisor",
    instructions="Write the brief from the notes. Tag every factual sentence.",
    tools=[researcher.as_tool(tool_name="research")],
)
```

Whether implemented via hierarchical agent managers in CrewAI or collection nodes in LangGraph,
the underlying execution pattern remains identical: execute worker extractions, aggregate note data,
and invoke a single synthesis call to generate grounded prose.

## Exercise overview

In this exercise, you will implement:
- `number_notes`: Assign deterministic `[S1]`, `[S2]` identifiers sorted by document ID.
- `synthesis_messages`: Construct supervisor prompts with indexed notes and tagging rules.
- `split_sentences`: Partition prose into sentences with abbreviation handling.
- `parse_claims`: Parse sentences into `Claim` objects, categorizing valid tags, unknown tags, and uncited statements.
- `write_brief`: Execute the supervisor call, meter token spend, and assemble the structured `Brief`.

The test suite verifies that synthesis executes in a single model call (`client.call_count == 1`) and correctly meters supervisor token usage.
