A generated research brief may contain accurate-looking citations where the cited text does not
appear in the source document, or where the prose misrepresents the excerpt.

Verifying citations requires a multi-stage validation pass: deterministic substring checks run first
to confirm the quote exists in the source text, followed by targeted model adjudication to verify that
the source passage supports the drafted claim.

## Prioritizing deterministic checks before model verification

Evaluating every claim with an LLM call is computationally expensive. Running deterministic substring
matching first filters out hallucinated quotes without consuming tokens:

```python
span = locate(note.quote, doc)
if span is None:
    return Verification(..., verdict="NOT_IN_SOURCE", span=None)
```

If the quote snippet does not exist in the source document, the claim immediately receives a `NOT_IN_SOURCE`
verdict. The pipeline only invokes a model judge when the quote is physically present in the reference document.

## Offset-preserving string normalization

Quotes extracted from formatted documents frequently differ in whitespace, capitalization, or punctuation
from the source text. Exact byte matching fails on benign formatting variations.

To match quotes reliably while preserving character offsets for redactions, normalize text into lowercase
alphanumeric characters while tracking source index mappings:

```python
characters, offsets = [], []
for index, character in enumerate(text):
    # normalize character while storing original source offset
    characters.append(character.lower())
    offsets.append(index)
```

The matching slice `offsets[found]` to `offsets[found + len(needle) - 1] + 1` maps the normalized match back
to the exact span in the original unnormalized document text.

## Constrained LLM claim adjudication

When a quote is verified to exist in the source document, an LLM judge evaluates whether the claim logically
follows from the cited passage. The evaluation prompt is strictly constrained: one claim sentence compared
against one extracted source passage.

The judge returns a structured tool call selecting from a closed set of verdicts:

```python
VERDICTS = ("SUPPORTED", "UNSUPPORTED", "NOT_IN_SOURCE")
```

Any unrecognized or malformed verdict defaults to `UNSUPPORTED` to ensure unverified claims do not pass
by default. Retaining the judge's diagnostic reasoning assists subsequent auditing.

## Redaction and verification reporting

The verification summary records overall status via `Report.ok`, which evaluates to `True` only when all
evaluated claims receive a `SUPPORTED` verdict and no uncited statements remain.

When unverified claims are detected, the system redacts the failing sentence directly within the generated prose:

```python
text = text.replace(sentence, f"[removed: {verdict}]")
```

In-place redaction highlights exactly which statements lacked evidentiary support while preserving verified
portions of the brief.

## Cost-benefit trade-offs of verification

Verification introduces additional model invocations proportional to the number of cited claims.
In exchange, deterministic string filtering catches fabricated quotes at zero token cost, and surviving claims
are validated against their source contexts.

For mission-critical reports and analytical briefs, rigorous verification prevents hallucinated assertions
from propagating into downstream decisions.
