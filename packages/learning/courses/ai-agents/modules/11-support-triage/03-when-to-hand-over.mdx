While the grounded answering layer operates statelessly, the session manager maintains conversation
history and evaluates state transitions across three distinct states:

```
[ answering ] -> customer requests human -> [ pushed back ]
[ pushed back ] -> customer requests human again -> [ escalated ]
[ escalated ] -> subsequent messages -> [ escalated ]
```

The session manager governs when to answer, when to offer one final automated attempt, and when to transfer control.

## Detecting escalation intent

Detecting requests for human assistance begins with targeted keyword and phrase matching.
A deterministic keyword matcher avoids unnecessary model latency and cost on every inbound message:

```python
WANTS_HUMAN = ("human", "real person", "agent", "representative", "someone else")
```

Effective keyword detection requires two filters:
- **Word boundaries**: Enforce regex word boundaries (`\b`) so terms like "human" do not match words like "humanities".
- **Phrase exclusions**: Mask technical computing phrases before matching to eliminate false positives:

```python
NOT_A_REQUEST = ("user agent", "agent string", "support agent", "this agent")

text = message.lower()
for phrase in NOT_A_REQUEST:
    text = text.replace(phrase, " ")
```

A customer reporting an issue with a "user agent string" is seeking technical help rather than a representative.
Production keyword filters maintain explicit exclusion lists to balance deflection and routing precision.

## Single pushback policy

A balanced escalation policy allows exactly one pushback attempt by default:

```python
def __init__(self, client, articles, max_pushbacks=1):
```

- **Zero pushbacks**: Escalates on the first trigger keyword, forfeiting automated resolution for users who might accept an immediate documentation answer.
- **One pushback**: Attempts to provide a helpful answer while respecting explicit user requests.
- **Multiple pushbacks**: Traps users in repetitive deflection loops, increasing frustration.

Certain high-risk workflows (such as billing disputes or safety concerns) may configure `max_pushbacks=0` to ensure immediate escalation.

## Contextual pushback retrieval

When a user says "Can I speak to a human?", retrieving articles against that phrase returns unhelpful results.
The pushback attempt must search against the user's preceding substantive question:

```python
def _topic(self, message):
    for role, said in reversed(self.transcript[:-1]):
        if role == "user" and not wants_human(said):
            return said
    return message
```

If a user asks "How do I reset my password?" and follows with "I want a person", the pushback retrieves
documentation for the password inquiry. If no prior query exists, the system falls back to the current message.

## Structured handoff payloads

When an agent escalates, it must supply the human operator with structured diagnostic context:

```python
@dataclass
class Handoff:
    reason: str
    summary: str
    attempted: list[str]
    article_ids: list[str]
    transcript_turns: int
```

- `summary`: One-line description of the initial inquiry and conversation length.
- `attempted`: Ordered list of automated responses previously sent to the user, preventing human agents from repeating suggestions.
- `article_ids`: Deduplicated list of knowledge base articles already referenced during the session.
- `transcript_turns`: Total count of user interaction turns.

Lists within the handoff payload must be copied to prevent mutation as subsequent session events occur.

## Terminal session state

Once escalated, the session enters a terminal state. Subsequent messages return the existing handoff payload
without triggering further model calls or article recommendations:

```python
if self.escalated:
    return self._say(ALREADY_ESCALATED_TEXT, "escalated", self.handoff)
```

Freezing the session prevents redundant model costs and ensures that multiple customer follow-ups append
to a single escalation ticket rather than generating duplicate queue items.

## Framework delegation comparison

Modern agent frameworks provide abstractions for routing and state delegation:

```python
# Reference example using the openai-agents package
from agents import Agent, handoff

billing = Agent(name="Billing specialist", instructions="...")
triage = Agent(
    name="Triage",
    instructions="Answer from the knowledge base. Hand off when the customer asks.",
    handoffs=[handoff(billing, on_handoff=log_handoff)],
)
```

While frameworks handle message routing, core policy decisions (escalation trigger rules, pushback limits,
and structured context payload formatting) remain application-level responsibilities.
