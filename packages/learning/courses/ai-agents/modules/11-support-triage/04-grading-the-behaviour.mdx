Single-turn evaluations measure whether individual replies match reference answers and invoke
expected tools. However, single-turn scoring misses conversational sequencing failures:
an agent may produce grammatically correct responses while prematurely escalating unprompted
or repeatedly refusing to hand over after multiple customer requests.

Evaluating support agents requires inspecting the complete multi-turn conversational sequence.

## Transcript structure

The evaluation harness records the entire interaction transcript:

```python
@dataclass
class Transcript:
    persona: str
    turns: list[tuple[str, SessionReply]]
    actions: list[str]
    handoff: Handoff | None
```

The `actions` list records the sequence of operational states (such as `answered`, `pushed_back`, or `escalated`).
Exposing actions explicitly simplifies writing clean validation predicates against the conversation trace.

## Behavioral rubric predicates

Rubric rules are implemented as deterministic predicates over the transcript:

```python
def pushed_back_once_before_escalating(transcript):
    if "escalated" not in transcript.actions:
        return True
    first = transcript.actions.index("escalated")
    return transcript.actions[:first].count("pushed_back") == 1
```

The standard rubric verifies five core properties:
1. All factual replies include valid citation markers.
2. The agent pushes back exactly once prior to escalating.
3. The agent hands over by the second explicit request for a person.
4. Escalations package a summary, attempted replies, and referenced article IDs.
5. Sessions that never request a human agent do not escalate.

Vacuous rule satisfaction is critical: if a transcript contains no escalation, rules governing escalation
behavior must return `True`. Failing unescalated sessions on escalation-specific rules would create incentives
for agents to escalate unnecessarily.

## Persona evaluation and calibration fixtures

The evaluation fixture tests four distinct customer personas:
- The cooperative user: receives an answer and ends the session without requesting a person.
- The frustrated user: registers complaints before requesting a human agent.
- The direct user: repeatedly demands an immediate human representative.
- The edge-case user: requests an invalid refund and challenges the refusal.

Including personas that never request a human verifies that the rubric does not inadvertently reward unconditional escalation.

The test suite also evaluates two deliberately misconfigured baseline sessions:

```python
class EagerSession(TriageSession):
    def __init__(self, client, articles):
        super().__init__(client, articles, max_pushbacks=0)


class StubbornSession(TriageSession):
    def __init__(self, client, articles):
        super().__init__(client, articles, max_pushbacks=1_000_000)
```

Calibrating against intentionally broken agents verifies that the rubric catches specific failure modes:
`EagerSession` must fail the single-pushback requirement, while `StubbornSession` must fail timely escalation requirements.

## Diagnostic evaluation reporting

Evaluation results aggregate persona scorecards and failure details:

```python
@dataclass
class SuiteResult:
    per_persona: dict[str, Scorecard]
    pass_rate: float
    failures: list[tuple[str, str]]
    ok: bool
```

`failures` lists specific `(persona, rule)` pairs to pinpoint regressions:

```
angry: pushed_back_once_before_escalating
wants-a-human: pushed_back_once_before_escalating
```

The `ok` flag evaluates whether the overall pass rate meets or exceeds the configured acceptance floor,
providing an automated gate for continuous integration pipelines.

## Live model evaluation considerations

The exercise runs entirely on `mockllm`. The following is a separate deployment pattern, not part of this
course's executable path:

```python
# Reference configuration for live model evaluation
def factory(persona):
    return TriageSession(OpenAI(), ARTICLES)

result = run_suite(factory, PERSONAS, floor=0.8)
```

- **Non-deterministic outputs**: Live model calls introduce variance. Track pass rates across repeated runs rather than relying on a single deterministic pass.
- **CI strategy**: Run offline, deterministic mock suites on every commit, and schedule live model evaluation suites on recurring batch jobs to manage inference costs and API rate limits.
- **Rule stability**: Behavioral predicates remain identical whether evaluating mock clients or production endpoints.

## Exercise overview

In this exercise, you will implement:
- `replay`: Execute a persona's scripted turns against a session and record the full `Transcript`.
- The five behavioral predicates evaluating grounding, pushback counts, and handoff payloads.
- `grade` and `run_suite`: Compute persona scorecards, overall pass rates, and failure diagnostics.

Ensure all predicates return `True` when the rule is not applicable to the transcript.
