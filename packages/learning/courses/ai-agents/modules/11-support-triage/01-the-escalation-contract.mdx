Support triage agents are widely deployed across production systems, but naive implementations
often fail. Treating support purely as a retrieval-augmented generation (RAG) task causes agents
to provide irrelevant documentation or frustrate users who require human intervention.

Effective support agents prioritize clear boundary management: recognizing knowledge limits,
grounding factual statements in retrieved documentation, and escalating cleanly to human operators.

## Support metrics: deflection versus resolution

Support systems typically track four core operational metrics:

1. **Deflection rate**: The proportion of sessions closed without creating a human support ticket. Deflection metrics alone can be misleading, as users who abandon frustrating interactions count as deflected alongside satisfied users.
2. **Resolution rate**: The proportion of sessions where the user's issue was successfully resolved. Measuring resolution requires follow-up surveys or transcript analysis.
3. **Escalation quality**: Whether the human agent who receives an escalated conversation receives sufficient context (summary, user intent, attempted steps) without asking the user to repeat information.
4. **Time to human**: The duration a user requiring human assistance spends interacting with automated prompts before transfer.

Evaluating support agents requires measuring both escalation quality and resolution accuracy rather than relying solely on raw deflection figures.

## Balancing premature escalation and aggressive deflection

Support agents navigate two competing operational failure modes:

- **Premature escalation**: The agent escalates immediately upon encountering unfamiliar phrasing, even when the knowledge base contains the answer. This inflates human support costs without using automated documentation.
- **Excessive deflection**: The agent repeatedly suggests articles despite direct user requests for human assistance. This damages user trust and creates poor customer experiences.

Evaluation rubrics must penalize both failure modes to ensure the agent resolves addressable questions while transferring unresolvable issues promptly.

## The escalation specification

The support triage agent implemented in this module adheres to the following operational contract:

- **Strict grounding**: Factual statements must cite retrieved knowledge base articles using bracketed identifiers (such as `[KB-12]`). Responses without supporting citations are rejected.
- **Zero-retrieval short-circuit**: If retrieval returns no relevant articles, do not invoke the language model. Route immediately to the human queue to prevent hallucinations and eliminate unnecessary token costs.
- **Explicit routing**: Out-of-scope queries trigger an escalation route rather than an unhelpful refusal.
- **Single-attempt pushback**: When a user explicitly requests a human agent, attempt automated assistance at most once. A second request must trigger an immediate handoff.
- **Contextual handoff payloads**: Handoffs must package the issue summary, attempted troubleshooting steps, and referenced articles for the receiving human agent.
- **Terminal handoff state**: Once escalated, the automated agent halts further model calls and suggestions.

## System architecture overview

You will construct the support triage system across three stages:

1. **Grounded answer engine**: Retrieves articles, formats the prompt, invokes the model, validates citations against retrieved context, and returns a structured `Reply` object with citation tracking and routing flags.
2. **Session manager**: Manages conversation history, enforces the single-pushback rule, builds `Handoff` payloads, and transitions the session into a terminal state upon escalation.
3. **Evaluation harness**: Executes test suites against multiple user personas, evaluating compliance against a five-rule rubric designed to identify both premature escalation and refusal loops.

## Out-of-scope concerns

To focus on core agent control flow and evaluation, this module omits:
- Direct CRM or live chat ticketing integrations.
- Vector database fine-tuning and specialized rerankers.
- Keyword sentiment classifiers. Routing relies on deterministic knowledge coverage and explicit user intent rather than sentiment heuristics.
